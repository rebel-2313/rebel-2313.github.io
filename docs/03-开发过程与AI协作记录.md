## 二、AI 参与的部分 vs 人工把关的部分

## 三、关键判断与取舍（答辩可展开讲的点）

1. **为什么保留原代码结构而不是重写？**
   初版已经把"内容（`content.js`）"和"渲染（`main.js`）"分开了，这个架构对一个会长期更新的个人网站是对的：四年里要不断加项目、加证书，改数据比改 HTML 安全得多。推倒重写等于丢掉这个优点，还容易引入新 bug。

2. **为什么正文用 JS 渲染，而不是直接写死 HTML？**
   一页 11 个板块若手写 HTML，改一个字段要在长文件里找位置，容易改错标签；用数据驱动只需改一行 `key: 'value'`。代价是"查看源代码看不到正文"，因此额外提供 `resume.md` 并处理了 `<noscript>` 提示，兼顾了"人和机器都能读"。

3. **为什么把霓虹特效大幅削弱？**
   求职场景的核心是"信息被读到"。跟随鼠标的准星、扫描线、故障闪烁属于展示型特效，在 HR 快速浏览时反而增加认知负担。保留一团极淡的微光，是保留"有设计感"的最低成本方式。

4. **为什么强调"诚实标注"？**
   初版里有编造的学校、年级和经历。这类信息在面试中一问就露馅，风险远大于收益。改版原则是：不确定的一律写 `【待填】`，"没做的"写成"计划中"，并把所有待填项汇总进 `docs/08`，避免遗漏。

5. **为什么先提交"未修改的初版"？**
   Git 的价值在于能对比"改了什么"。如果一开始就提交改完的版本，就丢失了"改版前长什么样"的证据。先提交基线，再分阶段提交，`git diff 7a0e4d3 HEAD` 就能完整展示这次改造。

## 四、踩过的坑与解决

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 初版内容与本人实际不符（学校、年级、参军经历） | AI 生成时按"典型大学生"模板填充，缺少真实素材 | 全部替换为结构化占位符 `【待填】`，由本人补齐；同时写 `docs/08` 清单逐项核对 |
| 新增板块后导航项变多，手机上挤成两行 | 导航是横向 `flex`，项目超过 7 个就换行 | 900px 以下把导航改为右上角菜单按钮 + 竖直下拉面板 |
| 课程、证书这类"列表型"内容用卡片排会很长 | 用了等比大卡片，信息密度低 | 改为"分组卡片 + 紧凑列表行"，右侧放时间/状态，一屏能看到更多 |
| 打印时背景色和装饰被一起打出来，浪费墨水且看不清 | 没写打印样式 | 增加 `@media print`：隐藏特效、顶栏、按钮，卡片去阴影、加细边框、避免跨页断开 |
| 亮色主题下顶栏半透明背景在旧浏览器失效 | `color-mix()` 较新 | 先写 `background: var(--bg)` 兜底，再用 `color-mix()` 覆盖 |
| **本地预览打开的是别人的页面** | 默认端口 8080 被另一个项目的预览服务占用，而旧脚本允许端口复用（`ExclusiveAddressUse = $false`），绑定"成功"了但请求被对方接走 | 默认端口改为 5180；启动前先真实探测端口是否有人应答，有人应答就跳过；绑定改为强制独占。实测：5180 返回本人页面，8080 返回他人页面（`易俊臣 — 个人主页`），修复后不再误判 |
| 无头浏览器截图在受限环境下起不来 | 渲染需要进程间通信（命名管道）被系统策略拦截 | 改用"导出渲染后的 DOM 再校验结构"的方式验证，同样能确认板块与字段是否生成 |

## 六、给自己的复盘

- **学到的东西**：静态站点的完整链路（内容设计 → 手写页面 → 版本管理 → 服务器部署）比"多写几个函数"更有价值；数据与视图分离是能受益四年的习惯。
- **做得不够的地方**：真实内容还没补齐；服务器还没买，部署环节只能先在本地验证；没做自动化的 HTML 校验（后续可加 `html-validate`）。
- **下次改进**：把项目详情拆成独立页面；做一个自动生成 PDF 简历的脚本，保证网页与 PDF 内容同源。
