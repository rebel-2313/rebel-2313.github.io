# 01 · 需求说明

> 项目名称：杨叶珥个人主页（求职向静态网站）
> 编写日期：2026-11-03
> 文档版本：v1.0

## 一、项目背景

课程要求每位同学制作一个个人介绍网站，并完成三件事：**写文档（Markdown）**、**用 Git 管版本**、**部署到云服务器**。网站本身不是一次性的作业，而是毕业求职时的"门面"，所以需求不能只按"交作业"来定，要按"HR 会怎么看"来定。

原始版本是早期用 AI 生成的"大学生日常日志"风格页面：霓虹赛博朋克风、内容偏向娱乐（我的一天作息表、食堂红黑榜、在玩的游戏、游戏累计 1200 小时）。它作为个人娱乐主页很合适，但作为求职材料存在三个问题：

1. **信息结构不对**：HR 想看教育背景、技能、项目、课程、证书，这些板块都没有；
2. **内容可信度不足**：大量编造信息（学校、年级、经历与本人不符），一旦被问到无法自圆其说；
3. **视觉干扰阅读**：跟随鼠标的光晕、准星光标、扫描线、故障闪烁，在求职场景里显得不够稳重。

因此本项目定位为：**在原有代码框架上改进**（保留"数据与视图分离"的架构和全部无障碍细节，不推倒重写），把内容与视觉改造成求职导向。

## 二、目标用户与使用场景

| 用户 | 场景 | 关心什么 |
| --- | --- | --- |
| HR / 面试官 | 简历里附了主页链接，点开看 30 秒 | 学校专业、技能、项目是否真实可讲、联系方式 |
| 老师 / 同学 | 课程验收、互相参观 | 结构是否完整、代码是否手写、部署是否成功 |
| 本人 | 每次有新项目、新证书时更新 | 改内容是否方便、会不会改坏、能不能重新部署 |
| 手机访客 | 微信里点开链接 | 排版是否错乱、加载是否够快 |

## 四、非功能需求

| 类别 | 要求 | 落实情况 |
| --- | --- | --- |
| 技术约束 | 纯手写静态页面，不使用 React/Vue 等框架与构建工具 | 仅 HTML + CSS + 原生 JS，无 npm、无编译 |
| 依赖 | 不加载任何 CDN 字体或库，断网可用 | 0 个外部请求 |
| 性能 | 首屏 < 1s，整站体积 < 300KB | CSS ≈ 22KB，JS ≈ 31KB，SVG 图 < 5KB/张 |
| 兼容性 | Chrome / Edge / Firefox / Safari 主流版本，Android / iOS | 使用 CSS 变量 + 渐进增强，旧浏览器降级不影响阅读 |
| 无障碍 | 语义化标签、键盘可达、焦点可见、尊重"减少动态效果" | 有跳转链接、`aria-*`、`:focus-visible`、`prefers-reduced-motion` |
| SEO | 有 title / description / 结构化数据 | 静态 head + JSON-LD `Person` |
| 可维护性 | 内容与视图分离，改文字不碰结构代码 | `content.js` 数据层 + `main.js` 渲染层 |
| 版本管理 | 全部源码与文档纳入 Git，关键节点有提交记录 | 见 `docs/04` |
| 部署 | 可部署到云服务器供公网访问 | 见 `docs/05` |

## 六、明确不做的事（范围边界）

- 不做后台管理系统、不做数据库、不做登录注册（静态站点的定位是"给人看"，不是"给人用"）
- 不引入前端框架或打包工具（课程要求手写，且会削弱"看得懂每一行"的收益）
- 不在页面上放手机号、身份证、家庭住址等敏感信息（公网可访问，只留邮箱与代码仓库）
- 不伪造经历：所有不确定的信息在页面上用 `【待填】` 标注，由本人补齐

## 七、验收标准

1. 本地双击 `index.html` 能完整显示 11 个板块，控制台无报错；
2. 手机（375px 宽）下无横向滚动条，导航可展开收起；
3. 亮/暗主题切换正常，刷新后保持选择；
4. 页面内所有 `【待填】` 有价值信息均由本人填写完成（`docs/08` 清单清零）；
5. `git log` 能体现完整开发过程，且每次提交可独立说明"做了什么、为什么"；
6. 云服务器上通过公网 IP 或域名能打开，且与本地效果一致。
