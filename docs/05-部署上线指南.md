# 05 · 部署上线指南（云服务器 + Nginx）

> 面向读者：第一次碰服务器的同学。照顺序做，每一步都有可验证的结果。
> 预计耗时：买机器 10 分钟，配置 30–40 分钟，域名与 HTTPS 另加 20 分钟（可选）。
> 适用系统：Ubuntu 22.04 / 24.04 LTS（阿里云、腾讯云、华为云的轻量应用服务器都可以）。
> 快捷方式：第五~七节的手工初始化已固化为脚本 `deploy/server-init.sh`，把 `deploy/` 目录传到服务器后执行 `bash server-init.sh` 即可一步完成（想理解原理仍可按下面步骤手动做）。买服务器的最优学生买法见 `docs/10`。

---

## 一、方案总览

```
你的电脑                          云服务器（公网 IP）
┌──────────────────┐   scp 上传   ┌───────────────────────────────┐
│ personal-site/   │  ─────────▶  │ /var/www/personal-site/        │
│  index.html      │              │   index.html, assets/ …        │
│  assets/         │              │        ▲                      │
└──────────────────┘              │        │ 读取                  │
                                  │   Nginx（80 端口）             │
                                  └────────┬──────────────────────┘
                                           │ http://公网IP/
                                     访客浏览器
```

- **为什么选 Nginx**：静态站点的标准做法，安装一条命令，配置文件十几行，是"服务器简单部署"最典型的形式。
- **为什么不用 Docker / Node**：纯静态页面不需要运行时，Nginx 已经把"发文件"这件事做到极致，加一层反而增加排查成本。
- **目录约定**：站点目录 `/var/www/personal-site`，Nginx 配置 `/etc/nginx/sites-available/personal-site`，备份 `/var/backups/personal-site`。

## 二、买服务器（最省事的选法）

| 项目 | 建议 | 说明 |
| --- | --- | --- |
| 厂商 | 腾讯云 / 阿里云 的「轻量应用服务器」 | 比 ECS/CVM 简单，控制台自带防火墙和监控，学生认证常有优惠 |
| 配置 | 2 核 2G / 40–60G 系统盘 | 放一个静态站绰绰有余，1 核 1G 也能跑 |
| 镜像 | **Ubuntu 22.04 LTS** | 教程命令与本文完全一致；选 CentOS 也能用，但包管理是 `yum/dnf`，需自行替换 |
| 地域 | 离你近的（如成都 / 重庆 / 上海） | 影响访问速度 |
| 带宽 | 3–5 Mbps 峰值即可 | 静态页面很小（整站 < 300KB） |
| 计费 | 包月/包年，先买 1 个月试 | 别一上来买三年 |
| 域名 | 可选 | 国内服务器绑域名**需要 ICP 备案**；没有域名可以先用 `http://公网IP/` 访问，同样满足"公网可访问" |

购买后要做的两件事：

1. **记下公网 IP**（控制台首页就能看到）；
2. **设置登录方式**：轻量服务器创建时可直接设 root 密码，或用 SSH 密钥。用密码更简单，但**密码要够长**。

## 三、开放端口（最容易漏的一步）

在云厂商控制台 →「防火墙 / 安全组」里放行：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 22 | TCP | SSH 远程登录 |
| 80 | TCP | HTTP 网站访问 |
| 443 | TCP | HTTPS（配了域名再开也行） |

> 只放行这几个就够。**不要**放行 3306、6379 等数据库端口，也不要图省事关掉防火墙。

---

## 四、连接服务器

在自己电脑上打开 PowerShell（Win + X → 终端），执行：

```powershell
ssh root@你的公网IP
```

- 第一次连接会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车；
- 然后输入密码（**输入时屏幕不显示任何字符，这是正常的**）；
- 看到 `root@vm:~#` 之类的提示符，说明已经登录成功。

如果提示 `Connection refused` / `timed out`：回到「三、开放端口」检查 22 端口；如果是公司或校园网，可能封了 22 端口，可换手机热点试。

## 五、服务器初始化（复制粘贴即可）

```bash
# 1. 更新软件源与已安装的包
apt update && apt upgrade -y

# 2. 设置时区为上海（日志时间才对得上）
timedatectl set-timezone Asia/Shanghai

# 3. 安装常用工具 + Nginx
apt install -y nginx curl vim git rsync ufw

# 4. 启动 Nginx 并设为开机自启
systemctl enable --now nginx
systemctl status nginx --no-pager

# 5. 开启系统防火墙（云控制台的防火墙也要放行，两层都要开）
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
ufw status
```

验证：浏览器打开 `http://你的公网IP/`，能看到 **"Welcome to nginx!"** 页面，说明服务器和网络都通了。这一步没通，后面都别做。

> 想更安全一点（可选）：用 `adduser deploy` 建普通用户，`usermod -aG sudo deploy`，之后用 `ssh deploy@IP` 登录，日常操作加 `sudo`；并编辑 `/etc/ssh/sshd_config` 设 `PermitRootLogin no`、`PasswordAuthentication no`（先配好密钥再用！）。新手建议先把网站跑通，再做这些加固。

## 六、准备站点目录

```bash
# 创建站点目录
mkdir -p /var/www/personal-site
chown -R www-data:www-data /var/www/personal-site

# 创建备份目录（部署脚本会用）
mkdir -p /var/backups/personal-site
```

先放一个测试页，确认目录与权限是对的：

```bash
echo '<h1>hello from /var/www/personal-site</h1>' > /var/www/personal-site/index.html
chown www-data:www-data /var/www/personal-site/index.html
```

## 七、配置 Nginx 站点

### 7.1 上传配置文件

在**自己电脑**的项目目录下执行（把 IP 换成你的）：

```powershell
scp deploy\nginx\personal-site.conf root@你的公网IP:/etc/nginx/sites-available/personal-site
```

或者不用上传，直接在服务器上 `vim /etc/nginx/sites-available/personal-site` 把 `deploy/nginx/personal-site.conf` 的内容贴进去（vim 里按 `i` 进入编辑，粘贴完按 `Esc`，输入 `:wq` 回车保存）。

### 7.2 启用站点

```bash
# 建立软链接启用
ln -s /etc/nginx/sites-available/personal-site /etc/nginx/sites-enabled/personal-site

# 关掉默认站点（否则 80 端口会被它抢走）
rm -f /etc/nginx/sites-enabled/default

# 检查配置语法：必须看到 "syntax is ok" 和 "test is successful"
nginx -t

# 重载配置（不中断服务）
systemctl reload nginx
```

再次访问 `http://你的公网IP/`，应该看到 `hello from /var/www/personal-site`。

## 八、上传网站文件（三种方式，选一种）

### 方式 A：一键部署脚本（推荐，以后更新都靠它）

在**自己电脑**的项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1 -Server 你的公网IP -User root
```

脚本会依次：打包 `index.html`、`resume.md`、`404.html`、`assets/` → `scp` 上传到 `/tmp` → 远程执行 `remote-deploy.sh`（自动备份线上版本、解包发布、`nginx -t` 校验、失败自动回滚、重载 Nginx）。

看到 `✅ 部署完成` 就好了。以后每次改完内容，重复执行这一条命令即可。

### 方式 B：图形化工具（不想碰命令行就用这个）

1. 下载安装 **WinSCP**（免费）；
2. 新建会话：协议 `SFTP`，主机填公网 IP，用户名 `root`，密码为服务器密码；
3. 左侧进项目目录，右侧进 `/var/www/personal-site`；
4. 把 `index.html`、`resume.md`、`404.html`、`assets` 文件夹拖到右侧；
5. 右键右侧目录 → 属性 → 确认所有者为 `www-data`（或在服务器上执行一次 `chown -R www-data:www-data /var/www/personal-site`）。

### 方式 C：先推到 Git 仓库，再在服务器上拉取（适合长期维护）

```bash
# 在自己电脑的项目目录
git remote add origin https://gitee.com/你的用户名/personal-site.git
git push -u origin main

# 在服务器上
cd /var/www
git clone https://gitee.com/你的用户名/personal-site.git personal-site-tmp
cp -a personal-site-tmp/index.html personal-site-tmp/assets personal-site-tmp/404.html personal-site-tmp/resume.md /var/www/personal-site/
chown -R www-data:www-data /var/www/personal-site
```

> 注意：不要把 `.git` 目录放到站点根目录对外提供（配置里已 `deny` 隐藏目录，但最稳妥是不放在 webroot 里）。

## 九、验收清单（公网可访问）

在**手机流量**（关掉 WiFi）下打开 `http://你的公网IP/`，逐项确认：

- [ ] 页面能打开，中文不乱码
- [ ] 11 个板块都在，导航点击能跳转
- [ ] 亮/暗主题切换正常
- [ ] 图片正常显示（头像、相册）
- [ ] 手机上没有横向滚动条，右上角菜单能展开
- [ ] `http://你的公网IP/404.html` 能打开（Nginx 已接管 404）
- [ ] 关掉 WiFi 用 4G 能访问（说明真的是公网可达，不是本地缓存）

命令行快速验证（在自己电脑）：

```powershell
curl -I http://你的公网IP/
# 期望看到 HTTP/1.1 200 OK 和 Server: nginx
```

## 十、绑定域名与 HTTPS（可选，但很加分）

### 10.1 域名解析

1. 在域名服务商（阿里云/腾讯云/Namesilo 等）购买域名；
2. 添加解析记录：类型 `A`，主机记录 `@`（及 `www`），记录值填**服务器公网 IP**；
3. 等 5–10 分钟生效，`ping 你的域名` 能看到这个 IP 就对了。

> **ICP 备案**：服务器在中国大陆时，域名必须完成备案才能通过 80/443 访问。备案走服务商流程，通常 1–20 个工作日。不想备案可以：用香港/海外服务器，或直接用 IP 访问。

### 10.2 免费 HTTPS

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名 -d www.你的域名
```

按提示输入邮箱、同意协议，certbot 会自动改写 Nginx 配置、申请证书、配置 80 → 443 跳转，并注册自动续期定时任务。验证：

```bash
curl -I https://你的域名/
systemctl list-timers | grep certbot     # 能看到续期任务即可
```

## 十一、日常更新流程（改完内容怎么上线）

```powershell
# 1. 改内容（只动 assets/js/content.js）
# 2. 本地看一眼：双击 index.html
# 3. 提交版本
git add -A
git commit -m "content: 补充 2027 年春季项目经历"

# 4. 一键部署
powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1 -Server 你的公网IP -User root

# 5. 浏览器 Ctrl + F5 强刷验收
```

> 静态资源缓存 7 天，如果你只改了 `content.js` 但页面没变化，是浏览器缓存，用 `Ctrl + F5` 即可。

## 十二、故障排查表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 浏览器打不开，一直转圈 | 云控制台防火墙没放行 80，或服务器上 ufw 拦了 | 两边都检查：控制台「防火墙」+ `ufw status` |
| 打开是 "Welcome to nginx!" | 默认站点没删，或站点没启用 | `rm -f /etc/nginx/sites-enabled/default` 后 `systemctl reload nginx` |
| 打开是 403 Forbidden | 目录权限不对 / 没有 index 文件 | `chown -R www-data:www-data /var/www/personal-site`，确认 `index.html` 存在 |
| 打开是 404 | `root` 路径写错，或文件传到了别的目录 | `nginx -t` 通过后看 `error_log`，确认文件确实在 `/var/www/personal-site` |
| 中文乱码 | 文件不是 UTF-8，或 Nginx 没设 charset | 编辑器里另存为 UTF-8；确认配置里有 `charset utf-8;` |
| 页面没样式（纯文本） | `assets/` 没传上去，或路径层级不对 | 确认 `/var/www/personal-site/assets/css/style.css` 存在 |
| 改了内容刷新没变化 | 浏览器/中间缓存 | `Ctrl + F5`；确认部署脚本真的执行成功 |
| `nginx -t` 报错 | 配置语法错、缺分号、站点重复 | 按报错行号改；`deploy/nginx/personal-site.conf` 是可用参考 |
| SSH 连接超时 | 22 端口未放行 / IP 被封 | 控制台检查防火墙；`ssh -v` 看卡在哪一步 |
| 部署脚本提示 sudo 需要密码 | 用的是普通用户且没配免密 | 直接 `sudo bash /tmp/remote-deploy.sh /tmp/personal-site.tar.gz` 手动执行 |

排查万能三连：

```bash
sudo tail -n 50 /var/log/nginx/personal-site.error.log   # 看错误
sudo systemctl status nginx --no-pager                  # 看服务状态
curl -I http://127.0.0.1/                               # 排除外网因素
```

## 十三、成本与安全提示

- **成本**：轻量服务器学生价常见 10–30 元/月，域名 30–60 元/年，HTTPS 免费。够用就好，不必买高配。
- **备份**：控制台开「自动快照」（每周一次），加上部署脚本的本地备份，双重保险。
- **别做的事**：不要在公网开放数据库端口；不要把 `.git`、服务器密码、密钥放进网站目录；不要用弱密码（建议 16 位以上随机串并保存到密码管理器）。
- **日志**：`/var/log/nginx/` 下的日志会一直增长，学习阶段无需处理，长期运行可加 logrotate。
