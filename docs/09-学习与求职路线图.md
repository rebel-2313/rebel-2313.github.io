# 09 · 学习与求职路线图（2026 – 2030）

> 这个网站要陪你四年。今天写的"计划"两三年后会变成"经历"，所以这份路线图是给**未来的自己**看的：
> 每个阶段该补什么、网站该更新哪一块、面试时该能讲什么。

---

## 一、总原则

1. **每个学期至少产出一个能跑的项目**，并写进 `projects`；
2. **技能只写真实掌握程度**，用"熟悉 / 会用 / 了解 / 正在学"四档标注；
3. **证书按"够用"考**：英语四级 → 计算机二级 → 一个有含金量的比赛或方向证；
4. **网站每学期更新一次**：课程成绩、项目、技能、最近在学；
5. **Git 记录别断**：哪怕只改一行文字，也提交一次，让提交历史成为成长记录。

## 二、阶段路线

| 方向 | 要完成的事 | 网站对应的更新 |

## 三、每学期的固定动作清单

```text
[ ] 学期末：更新 courses 里的成绩与"一句话收获"
[ ] 学期末：把新学的技术加进 skills（标注掌握程度）
[ ] 有新项目：加进 projects，写清角色 + 技术栈 + 3 条关键工作
[ ] 有证书/奖项：加进 certs，状态改"已获得"
[ ] 更新 now（最近在学）与 footer.updated
[ ] git add -A && git commit -m "content: 更新 20xx 学年秋季学期内容"
[ ] 部署：powershell -File deploy\deploy.ps1 -Server IP -User root
[ ] 手机 4G 打开验收一次
```

---

## 四、判断"这个项目值不值得写"的三条标准

1. **我能讲 3 分钟**：能说清需求、方案、难点、解决过程、结果；
2. **有可验证的东西**：仓库链接、截图、数据、别人在用；
3. **和我投的岗位相关**：不相关的玩票项目宁可不写，或压缩成一条。

---

## 五、给大一自己的三句话

1. **先把基础课学扎实**，大一的 C 语言和数据结构，是后面所有面试题的根；
2. **不要等到"学好再做项目"**，边做边学才是最快的学习方式，这个网站就是证明；
3. **诚实比包装重要**，网站上的每一个字，都要能经得起面试官追问一遍。
