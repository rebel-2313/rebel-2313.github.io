# 00 · 实施方案与验收对照

> 项目名称：杨叶珥个人主页（求职向静态网站）
> 编写日期：2026-11-17 · 文档版本：v1.0
> 面向读者：任课老师（验收对照）+ 本人（执行清单）
> 一句话概括本方案：**不追求技术炫技，追求"每一块都能被验收、每一行都能讲清楚"。**

---

## 一、方案要点（先看这一页）

| # | 决策 | 选择 | 为什么不选另一个 |
| --- | --- | --- | --- |
| 1 | 技术栈 | 原生 HTML / CSS / JavaScript，零框架、零 CDN | 用 Vue/React 要引入构建工具，出问题时我分不清是"我写错了"还是"配置错了"，对大一反而更难 |
| 2 | 内容组织 | 数据与视图分离：文字全在 `content.js`，渲染在 `main.js` | 内容写死在 HTML 里，改一句话要在十几个 `<section>` 里找，改一次错一次 |
| 3 | 版本管理 | Git 单主干 `main` + Conventional Commits | 走 Git Flow（develop/release/hotfix）一个人开发用不上，反而增加记分支的成本 |
| 4 | 部署方式 | 云服务器 + Nginx 反向代理静态目录 | 不用 Docker：纯静态文件没有运行时依赖，加一层只会让排查从 1 步变成 3 步 |
| 5 | AI 的角色 | AI 负责"生成与解释"，我负责"判断与验收" | 让 AI 一把梭生成整站，答辩时问一句"这段为什么这么写"就答不上来 |

## 四、AI 承担什么、我承担什么

这一节是为了回答老师最可能的质疑："这是 AI 写的吧？"

| 环节 | AI 做的 | 我做的 |
| --- | --- | --- |
| 需求梳理 | 把老师的话整理成 12 项验收表 | 判断优先级：先保"老师明确要的"，再做加分项 |
| 代码 | 生成渲染函数、CSS 变量体系、Nginx 配置初稿 | 逐个函数读懂，改掉不符合预期的部分；自己排查"端口被占用打开别人页面"的 bug |
| 内容 | 按模板生成结构化占位符 | **所有真实信息（学校、成绩、项目）只由我填**，AI 不知道也不该编 |
| 文档 | 起草文档结构与表格 | 补入真实过程、真实报错、真实耗时 |
| 验收 | 提供检查清单 | 真的去跑命令、看页面、截图 |

**判断标准很简单**：答辩时如果被问到"这里为什么这么写"，我能不能不打开电脑就回答出来。答不上的部分，就是还没真正学会的部分，要重写。

## 五、本次整改做了什么（2026-11-17）

| 改动 | 问题 | 做法 | 影响 |
| --- | --- | --- | --- |
| 单一数据源重构 | 学校名在页面里出现 6 处（关于我、教育背景、成长轨迹、JSON-LD…），改一处漏一处就会出现"正文 A 大学、教育背景 B 大学"的矛盾 | `content.js` 顶部定义 `SCHOOL` / `COLLEGE` / `MAJOR` 三个常量，其余位置全部引用 | 维护点从 6 处 → **1 处** |
| 死链过滤 | 联系方式里 `https://github.com/yourname` 指向一个陌生人的主页，`href: ''` 还会渲染成点了没反应的假按钮 | `main.js` 渲染前过滤掉空地址；未填的社交链接不显示 | 页面上不再出现假链接 |
| 简历入口 | 页脚写着"简历 PDF 可邮件索取"，但访客没法直接看 | 联系方式增加「Markdown 版简历」入口，指向 `resume.md` | 访客 1 次点击即可看简历 |
| 方案文档 | 老师要求"讨论一个实施方案"，但仓库里只有需求说明，没有"要求 → 交付物 → 证据"的对照 | 新增本文档 | 验收时可以逐条打勾 |

## 六、超额完成的加分项（对应老师问的"还有什么建议"）

这些不是老师要求的，但对"毕业找工作"这个真实目标有用，且都已经做完了：

| 加分项 | 有什么用 |
| --- | --- |
| 结构化数据（JSON-LD `Person`） | 搜索引擎能把你识别成"一个人"，搜索结果更规范 |
| `og:` / `twitter:` 卡片 | 链接发到微信、QQ 时显示标题和描述，而不是一串网址 |
| 打印即简历（`@media print`） | `Ctrl + P` 直接导出干净的 PDF，不用另外维护一份 Word |
| 亮 / 暗双主题 + 跟随系统 | HR 用暗色模式打开不会刺眼，体验上先赢一档 |
| 手机自适应 + 移动端菜单 | 一半以上的访客是手机点开的 |
| 键盘可达 + `skip-link` + `aria` 标注 | 无障碍是工程素养的体现，也常被面试官注意到 |
| 零依赖、断网可用 | 不用 CDN，打开快、不会因为墙或 CDN 挂掉而白屏 |
| 404 页 | 输错地址不会看到服务器默认的报错页 |
| 数据与视图分离 | 改内容不用碰逻辑，这是本项目最值得讲的设计 |
| 测试清单（`docs/07`） | 交付前有据可查，不是"我觉得没问题" |

**还没做、建议下一步做的**（写在这里是为了让老师看到规划能力）：

1. **项目详情页**：现在项目只是卡片，做到 3 个以上项目时应该拆成独立页面；
2. **网页与 PDF 同源**：用脚本从 `content.js` 生成 PDF 简历，避免手动同步两份；
3. **访问统计**：加一个极简的计数（不引入第三方追踪），知道有没有人看；
4. **自动化校验**：把 `docs/07` 的检查项写成脚本，提交前自动跑一遍。

## 七、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 真实信息填不全，页面到处是 `【待填】` | 老师/HR 一看就像半成品 | 按 `docs/08` 清单逐项清；**宁可删掉该项，也不要留着占位符上线** |
| 没买云服务器，要求⑤无法验收 | 直接影响成绩 | 见下方"最小可行上线路径"，最便宜的学生机即可 |
| 学校名、成绩属于个人隐私 | 公开到公网可能被爬 | 成绩可写"专业前 20%"而非具体排名；不想公开的字段直接删 |
| 只有本地 Git，没有远程仓库 | 电脑坏了代码就没了，老师也看不到过程 | 推一份到 Gitee（国内快、免费私有仓库），见下方 |
| 大一学业压力大，网站做完就烂尾 | 大四找工作时内容全是四年前的 | 每学期更新一次 `courses` / `projects` / `now`，见 `docs/09` |

### 最小可行上线路径（要求⑤）

| 步骤 | 做什么 | 花多久 | 花多少钱 |
| --- | --- | --- | --- |
| 1 | 买一台轻量应用服务器（Ubuntu 22.04，1 核 2G 够用） | 10 分钟 | 学生机约 60–100 元/年 |
| 2 | 按 [docs/05](05-部署上线指南.md) 第一节装 Nginx | 15 分钟 | 0 |
| 3 | 执行 `deploy\deploy.ps1 -Server 公网IP -User root` | 3 分钟 | 0 |
| 4 | 浏览器打开 `http://公网IP/`，截图存档 | 2 分钟 | 0 |
| 5 | 回填 `docs/05` 第十四节「部署记录」+ `docs/04` 打 tag | 5 分钟 | 0 |

> 域名和 HTTPS 属于加分项，不是必需：**先用 IP 访问把流程跑通，再考虑域名**。

### 远程仓库（补 Git 的完整性）

```bash
# 在 Gitee 建一个空仓库（私有即可），然后：
git remote add origin https://gitee.com/你的用户名/personal-site.git
git push -u origin main
```

推上去之后，老师可以直接看提交历史，你也不怕电脑坏。
